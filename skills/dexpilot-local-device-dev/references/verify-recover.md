# 验证、恢复和退出

## 分层核验

| 层级 | 必须看到的证据 | 不能用什么替代 |
| --- | --- | --- |
| 来源 | 组件 ID/精确版本/平台/大小/哈希，入口与归档验证 | 文件名或下载 HTTP 200 |
| 安装 | 安装回执和真实 modules/linkDirectory，完整性通过 | 目录存在 |
| 激活与启用 | 对应方案 active、信任、权限、未显式禁用 | disabled 数组为空或单独 active.json |
| SDK 准备 | 托管已支持 SDK 的 ready/错误原因，入口实际可准备 | 原生 SDK ZIP 存在或前端 npm SDK 已装 |
| 运行视图 | 当前候选与 admission 的正确 Adapter/SDK 对应路径 | 历史 backend-plugin-directory 路径 |
| Host | 正确 PID/入口/配置/端口，健康成功且会话握手成功 | 单独 /api/health 200 |
| 注册 | scan 回执、Adapter 名/版本/路径与本次目标匹配 | 扫描命令已发送 |
| 设备 | 正确实例/SN，enabled/mounted/READY 等状态有来源 | 模拟 SN、界面默认 connected |
| 数据 | 实际 kind/subkind、帧计数/时间戳持续变化、页面显示来自同一实例 | 单元测试或静态 payload |
| 退出 | 自有 Host/Adapter/SDK 进程树已退出，锁/端口释放 | 关闭窗口或 kill 命令返回 0 |

当请求只要求启动环境，完成到可用环境并报告设备连接/采集尚未执行；不要擅自校准、重启硬件、开始录制或运动控制。用户已要求连接/采集时，在指定型号范围内继续完成真实验证。

可使用后端已有 Gateway 工具读 health/instances/devices/streams；其 GW_URL、凭据、token 缓存必须与本次 Host 对应。不要回显 token、沿用共享 /tmp 缓存导致串账号，也不要把文档里的示例 secret 当当前认证。

状态检查可经 Desktop UI 或已有 API 工具完成；`device:scan_adapters` 属于 admin 操作并可能替换/卸载旧实例，必须先确认维护范围。插件包安装成功与后端设备自动挂载是不同步骤。

## 常见失败与恢复

| 现象 | 下一步 |
| --- | --- |
| Host 不认识 --adapter-dirs | 核对实际二进制 help；当前源码重新构建至新路径，不把 plugins/ 传给 --adapter-dir |
| 前端能打开，但无设备 | 依次检查原生安装/启用、SDK 准备、admission、scan 回执、实例挂载与流；不先改 UI 假数据 |
| SDK pending/preparing | 观察同一准备任务/进程与日志；冷启动解包可能较慢，超过提示阈值不代表崩溃，不反复重启 |
| SDK failed | 定位入口、平台、执行位、供应商依赖、当前用户目录/权限；修复后用「重试准备」，不要删 SDK 缓存/标定盲试 |
| health 通但登录失败 | 保留健康 Host，处理当前账号/License/握手；不假设默认用户名，不自动重置或关闭鉴权 |
| 已启用但 runtime rejected | 检查信任、摘要、入口、平台、缺少 SDK 或共享 Adapter 绑定冲突，修正完整方案 |
| 扫描无变化 | 核对 Host 实际 argv 与所有 YAML 根；--adapter-dirs 会合并 YAML，确认不是扫旧目录；读取 rejected/scan_in_progress |
| 端口冲突 | 核对所有者，复用正确服务或选新端口；受管端口可能自动更换，应回读 |
| 停止未确认 | 保留所有权，阻止重复启动/覆盖；核对确切 PID/进程组，不按名称 killall |
| 安装锁被占用 | 确认安装/准备进程是否仍活跃；活跃或未知所有者不删锁、不强制回收 |
| 源码/CLI 文档矛盾 | 用当前实现、测试与实际 help 交叉确认，标记差异，不选方便的说法 |

当前托管 Host 确定意外退出后按 1/3/10 秒最多三次恢复，先回收旧进程；稳定运行后重置额度。普通 SDK 准备失败不等于全局 Host 故障。自动恢复失败提供手动重试；取消/主动停止/应用退出不自动重启。参数是基线行为，执行时看目标源码和日志，不新增外部无限重试循环。

## 安全退出

1. 停止本次明确启动的采集/录制并等待终态，记录未确认结果；释放页面流和工作任务。
2. 托管模式先使用 Desktop 的停止/退出路径，等待 launcher 回收自有 Host 与 SDK 准备/运行子进程；外部模式只停止本任务拥有且授权停止的终端/PID。
3. macOS/Linux 先 SIGTERM/前台 Ctrl-C，再按已有控制器处理超时；Windows 仅在确认自有 PID 后按现有进程树机制回收。不操作同名其他进程。
4. 核验 PID、子进程与端口；进程查验被权限阻止时报告未知，不声称已全部结束。
5. 保留运行配置、日志和安装回执以便复现；只清理本次创建且已不用的临时产物，不清用户数据或供应商缓存。

基线 Desktop 有最长约 25 秒退出兜底。应用退出不证明所有不明子进程已退出；若有 HOST_STOP_UNCONFIRMED，保存诊断并在下一次启动前核验，不能为了「可重启」忽略所有权保护。

## 结果报告模板

列出：模式、型号/实例、平台、Desktop/Host 路径与 PID、实际网关 URL、userData/插件库/Host data、各组件版本与来源、已到达的核验层级、剩余阻塞、停止和再次启动方法。明确区分源码静态验证、无设备夹具、Electron 联调和真机数据。
